# OSA — персональный AI-агент

OSA (Оса) — персональный агент в духе JARVIS: разговаривает, планирует и выполняет задачи на компьютере, безопасно пользуется инструментами, восстанавливается после ошибок и ведёт телеметрию. Голос — это интерфейсный слой вокруг агента.

```text
OSA ≠ конкретная LLM

OSA = agent system + memory + actions + safety + recovery + autonomy + observability
LLM = заменяемый интеллектуальный backend
```

- **Текущая версия:** 1.5.0 (Clean Cognitive Core, нативный tool calling)
- **Платформы:** macOS (основная разработка, MacBook Air M1, 8 ГБ) и Windows (целевой ПК: Ryzen 5 5500, RX 6600 8 ГБ, 16 ГБ RAM)
- **Python:** 3.12–3.13
- **Тесты:** 1561 passed, 8 skipped на macOS (пропущены только живой звук, Windows UI Automation и Playwright Chromium)
- **Модель по умолчанию:** Qwen2.5-VL-3B-Instruct (Q4_K_M + mmproj Q8_0) через локальный `llama-server`

> Статус документа: составлен 2026-10-04 по реальному состоянию репозитория. Всё, что не проверено кодом или тестами, помечено «не проверено».

## Быстрый старт

Зависимости пока ставятся частично вручную (упорядочим в 1.5.1.6).

```bash
git clone https://github.com/Kirill555333/OSA.git
cd OSA
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,voice]" numpy sounddevice
```

Для браузера нужен `playwright` (`pip install playwright`), на Windows для слоя рабочего стола нужен `pywinauto`.

**1. Положите модель в `models/`** (папка в `.gitignore`, файлы в git не попадают):

- `Qwen2.5-VL-3B-Instruct-Q4_K_M.gguf`
- `mmproj-Qwen2.5-VL-3B-Instruct-Q8_0.gguf`

**2. Запустите сервер llama.cpp** (флаг `--jinja` обязателен для нативного вызова инструментов):

```bash
llama-server \
  -m models/Qwen2.5-VL-3B-Instruct-Q4_K_M.gguf \
  --mmproj models/mmproj-Qwen2.5-VL-3B-Instruct-Q8_0.gguf \
  --port 8080 --jinja -c 8192 -ngl 99 -np 1
```

**3. Запустите OSA:**

```bash
osa --check      # проверка, что сервер на 127.0.0.1:8080 отвечает
osa              # интерактивный режим (или: python -m osa.main)
osa --version
```

В диалоге можно печатать текст или нажать пустой Enter для ввода голосом. Выход: `exit`, `выход`, `/quit` или Ctrl+C.

**Тесты и проверки:**

```bash
python -m py_compile <файлы>
ruff check src tests
pytest -q
git diff --check
```

## Архитектура

```text
        Пользователь (текст / голос / автономная задача)
                          │
                       Agent ───────── ContextManager (бюджет, компактизация, summary)
                          │                    │
                          │              Memory Retriever ── LongTermMemory (SQLite)
                          │
                    ModelInterface ── LlamaCppModel (llama.cpp, OpenAI-совместимый API)
                          │
                    tool calls
                          │
                ActionSafetyPipeline
        (режим → разрешения → безопасность → подтверждение)
                          │
                     ActionRouter
                          │
             ToolRegistryActionAdapter ── Tools
                          │
     Recovery  ·  ExecutionContext  ·  Observability (с редактированием секретов)
```

Ключевые контракты (не меняются без отдельного архитектурного решения):

- `ActionRequest` / `ActionResult` — неизменяемые, `request_id` канонический.
- `ExecutionContext` — канонические `request_id`, `run_id`, `task_id`, `source`, `round_number`; в автономном режиме `round_number` запрещён.
- Recovery не может обходить safety; повтор после успеха запрещён.
- Observability не хранит сырые аргументы и вывод инструментов, секреты маскируются.

### Карта `src/osa`

| Пакет | Назначение |
|---|---|
| `core/` | Agent, режимы (chat/task/research/autonomous), ExecutionContext, голосовые и recovery-интеграции |

| `browser/` | HTTP-браузер, Playwright, безопасность браузера |

| `tasks/` | Автономный цикл, исполнитель, верификация, восстановление |
| `recovery*` | Контракты, политика, ограничители и верификация восстановления |
| `observability/` | События, логирование, запросы к логам, редактирование секретов |

| `research/`, `planning/`, `shell/`, `system/`, `utils/` | Веб-исследование, планировщик, консоль, платформенные провайдеры, служебное |

## Известные проблемы 1.5.0

Найдены при разборе кода 2026-10-04. Исправление запланировано в 1.5.1.

**Работа с окнами и ссылками**

1. `models/local.py`, запасной разбор текста: если в ответе модели упомянуто имя инструмента, регулярка выдумывает вызов с подстановкой по умолчанию (`https://google.com`, Enter, громкость 30, Chrome). Там же словарь псевдонимов приложений; его дубль лежит в `tools/desktop.py`.
2. Готовые `DesktopActionAdapter` и `DesktopActionSafetyPolicy` (подтверждения, защита Terminal и VS Code, блокировка `Cmd+Q`) не подключены к агенту: в `ActionRouter` зарегистрирован только `ActionKind.TOOL`. Инструменты рабочего стола ходят в `subprocess` в обход слоя `desktop/` и его проверок.
3. Нет инструментов «список окон», «сфокусировать окно», «список приложений», хотя слой `DesktopAutomationInterface` это умеет.
4. `main.py` вызывает `agent.reset()` после 10 сообщений, что стирает контекст и summary `ContextManager`. Лимит `max_tool_rounds=5` при превышении приводит к откату контекста: действия выполнены, а агент о них «забыл».
5. `inspect_screen` обращается к `127.0.0.1:8080` напрямую, минуя `ModelInterface`.
6. Системный промпт содержит остатки Qwen3 (`/no_think`) и жёстко прописанные примеры запросов.

**Безопасность и кроссплатформенность**

7. `launch_application` и `open_url` на Windows передают строку от модели в `shell=True`. `open_url` на macOS жёстко использует Google Chrome.
8. `scroll_mouse` и `set_volume` на Windows возвращают успех, ничего не делая.
9. `close_application` в `main.py` имеет разрешение ALLOW, на macOS использует `pkill -i -f` по подстроке, на Windows `taskkill /F`.
10. Рабочая папка файловых инструментов и shell равна `Path.cwd()`; память и логи создаются там, откуда запущен OSA.

**Проект и окружение**

11. Версии не сходятся: `version.py` 0.4.5, `pyproject.toml` 0.2.12, `CHANGELOG.md` 0.3.10, `main.py` 1.5.0. В `pyproject.toml` пустые `dependencies`.
12. Флаги `--voice` и `--listen` разбираются, но не используются; файлы `config/*.yaml` пустые и не читаются.
13. `ModelConnectionError` определён дважды (`models/interface.py` и `models/local.py`). Возможная бесконечная рекурсия `generate_stream` ↔ `generate_stream_events` в базовом классе (не проверено тестом).
14. `ARCHITECTURE.md`, `ROADMAP.md`, `.env.example` пустые.

**Результаты диагностики (подэтап 1.5.1.0)**

- `AgentModePolicy` скрывает от модели только `web_research` вне режима research. Гипотеза «инструменты 1.5 скрыты политикой режима» не подтвердилась.
- В журнале `logs/osa-events.jsonl` последние записи относятся к периоду облачного эксперимента: HTML вместо ответа API и некорректный адрес локального сервера (`127.0.0`). Событий с вызовами инструментов в этом отрезке нет, поэтому реальное поведение `main` нужно записать свежим запуском.
- Не проверено: значения по умолчанию `ContextBudget.create()` (нужно сверить с `-c` сервера).

**Инварианты безопасности:**
- строки от модели никогда не попадают в shell;
- закрытие приложений и окон, а также опасные хоткеи требуют подтверждения; Terminal и VS Code защищены;

- неподдержанное действие никогда не считается успехом.

**Не меняем:** `ActionRequest`, `ActionResult`, `ExecutionContext`, внутренности `ContextManager`, память, голосовую архитектуру, контракты recovery.

**Публичный API:** добавляются `list_applications`, `list_windows`, `focus_window`; удаляются `COMMON_APP_MAP`, `extract_app_from_text`, `POPULAR_ALIASES` (сначала проверить, не импортируются ли они тестами).

**Критерии завершения:**
- полный набор тестов зелёный;
- сценарии «открыть приложение», «открыть ссылку», «показать окна», «сфокусировать окно», «три действия подряд» проходят на Fake-слое и руками на macOS;
- в коде нет `shell=True` со строками от модели;
- одна версия во всех местах.

**Порядок:** подэтапы по номерам; 1.5.1.0 блокирует остальные, его результат может изменить 1.5.1.2. Checkpoint после 1.5.1.4 и после 1.5.1.8.

## Правила разработки

Эти правила действуют и для людей, и для ассистента, с которым ведётся разработка.

1. **Сначала архитектурный план** новой большой версии (цель, архитектура, подэтапы, зависимости, инварианты, публичный API, намеренные «не меняем», тесты, критерии), и только потом код.
2. **Реальный API.** Ничего не выдумывать: перед правкой файла сверяться с актуальным кодом в репозитории.
3. **Полная замена файла** (`cat > file <<'PY' … PY`) вместо инструкций «добавь эти строки».
4. **Порядок проверки:** syntax → `ruff` → целевые тесты → полный `pytest -q` → `git diff --check`. С красными тестами дальше не идём. Если тест не соответствует реальному API, исправляется тест, а не production-код.
5. **Сигнал `//`** означает «всё зелёное, продолжаем».
6. **Checkpoint** (`git add -A && git commit -m "checkpoint: …" && git push`) после половины версии и в конце. Факт commit и push подтверждает только вывод терминала.
7. **Идентификаторы** (`request_id`, `run_id`, `task_id`) живут в одном месте и не дублируются в metadata.
8. **Без регулярок и хардкод-словарей** для разбора намерений пользователя: выбор действий делает модель через структурированный tool calling.

## Безопасность репозитория

- Секреты только в `.env` (в `.gitignore`), шаблон без значений в `.env.example`.
- Не коммитить: ключи и токены, `models/`, `*.gguf`, `data/*.db`, `logs/`, скриншоты.
- Перед `git push` проверять: `git status`, поиск ключей по `grep -rIn -E "sk-|ghp_|API_KEY"`.
- Если секрет попал в git или в публичное место, его нужно отозвать у провайдера; удаление файла не убирает его из истории.
